# 部署条件与工具选型矩阵

> 核心原则：**方法论通用，工具按部署条件选择。**

## 四级部署阶梯

### 第 0 级 · 零部署（只有浏览器 + LLM API）

**适合**：想先看方法论、评估是否值得投入的人。

| 可用 | 说明 |
|------|------|
| 全部方法论文档 | `methodology/` 四法 |
| knowledge-map-viewer | 本地打开，手动贴 JSON 即可渲染 |

**不需要**：任何服务器、任何安装。

### 第 1 级 · 纯本地（OpenClaw 跑在本机）

**适合**：个人使用，无远程/多设备需求（A 类受众）。

**额外可用**：
- 论文调研脚本（只需 LLM API）
- 文件列车纯本地模式（file:// + 本地 manifest.json）

**不需要**：文件列车远程版、对象存储、域名。

### 第 2 级 · 内网 NAS（局域网多设备）

**适合**：家庭/工作室 NAS，局域网内手机/平板访问。

**额外可用**：
- 文件列车内网部署（NAS 静态服务 + 内网域名）
- 局域网访问无需公网域名，无需 HTTPS（非必需）

### 第 3 级 · 公网服务器（ECS / 云主机）

**适合**：需要随时随地访问、对外分享（B 类受众）。

**额外可用**：
- 文件列车完整版（对象存储 + 公网域名 + HTTPS）
- 知识地图远程内联渲染（viewer 与 JSON 同源部署）

## 工具 × 级别矩阵

| 工具 | 0 | 1 | 2 | 3 | 依赖 |
|------|:-:|:-:|:-:|:-:|------|
| 方法论（全部） | ✅ | ✅ | ✅ | ✅ | 无 |
| knowledge-map-viewer | ✅ | ✅ | ✅ | ✅ | JSON Schema |
| 论文调研脚本 | ✅ | ✅ | ✅ | ✅ | arXiv + LLM API |
| 文件列车（本地） | — | ✅ | ✅ | ✅ | 无 |
| 文件列车（内网） | — | — | ✅ | ✅ | NAS 静态服务 |
| 文件列车（公网） | — | — | — | ✅ | 对象存储 + 托管 + 域名 |

## 无服务器用户的替代方案

**问：我没有 ECS，能用文件列车吗？**

答：可以，有三条路径：

| 路径 | 做法 | 代价 |
|------|------|------|
| 纯本地 | file:// 打开 + 本地 manifest.json | 无远程访问 |
| GitHub Pages | 静态托管 HTML + manifest | 境外访问可能慢 |
| 免费对象存储静态网站 | 阿里云 OSS / Cloudflare R2 静态托管 | 需配 CORS |

**问：文件列车 vs 直接发文件链接？**

- 文件列车：统一入口、分组浏览、知识地图内联渲染、卡片化
- 直接链接：单文件、无管理界面
- 建议：产出物 <10 件/周 → 直接链接即可；持续高频产出 → 文件列车

## 部署示例（文件列车 · 公网版）

```
1. 准备：对象存储（如 OSS）+ 静态托管（如 ECS + Nginx）
2. 上传：文件列车.html → 托管根目录；manifest.json → 同源可 fetch 路径
3. 配置：HTML 中 MANIFEST_URL='https://your-domain/serving/manifest.json'
4. CORS：OSS/托管端允许该域名的 GET 请求
5. 更新流程：新产出 → 上传资源 → 更新 manifest.json（version+1）→ 前端自动刷新
```
