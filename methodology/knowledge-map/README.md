# 知识地图法（Knowledge Map Methodology）

> 版本: v1.0 | 来源: 实战提炼（2026-07 起多张地图实践：世界大模型、量化交易、AI 实验方法论）

## 核心思想

知识地图是一种**数据结构规范 + 构建方法**，让知识可以：
- **可视化**（力导向图 + 结构树双视图）
- **可演进**（分层构建，每层确认后推进）
- **可复用**（JSON 格式，任何工具可按 schema 渲染）

核心理念：**节点是平级的知识点，分类通过标签（tags）实现，不支持层级嵌套。**

## 一、文件结构（三段式）

```
┌─────────────────────┐
│ 文件头（元数据）     │  → 版本、tags_schema
├─────────────────────┤
│ 主体（节点列表）     │  → 平级的知识节点
├─────────────────────┤
│ 附录（关系列表）     │  → 节点间的拓扑关系编码
└─────────────────────┘
```

## 二、节点定义

### 必填字段

| 字段 | 说明 |
|------|------|
| `node_id` | 唯一 ID（如 `sec_xxx`） |
| `title` | 标题 |
| `tags` | 分类标签（3-8 个），决定可视化颜色 |
| `status` | `fulfilled` / `growing` / `archived` |
| `year` | 年份（时间线轴定位） |
| `created` / `updated` | 创建/更新时间 |

### 可选字段

- `maturity`（理论类地图用）：`经典闭环` / `成熟未闭合` / `有论文支撑` / `概念阶段`——描述学术共识程度，与个人学习状态（status）正交

### 升格条件（何时成为独立节点）

满足任意一条：
1. **被引用**（有其他节点指向它）
2. **有声明关系**（它指向其他节点）
3. **独立生命周期**（状态不随父节点变化）
4. **跨领域引用**（被其他知识地图引用）

## 三、关系编码

### 六类关系

| 编码 | 含义 | 可视化 |
|------|------|--------|
| `depends_on` | 依赖 | 蓝色实线 |
| `replaces` | 替代 | 橙色实线 |
| `triggers` | 引发 | 黄色点线 |
| `conflicts` | 冲突 | 红色虚线 |
| `supports` | 印证 | 绿色实线 |
| `subtopic_of` | 包含 | 紫色实线 |

### 证据 Tag（必填）

| 证据 | 含义 | 权重 |
|------|------|:----:|
| `#原文引用` | 原文直接声明，可追溯页码/段落 | 高 |
| `#结构推导` | 从文档逻辑结构推知，可验证 | 中 |
| `#领域推断` | 基于领域知识的推断 | 低 |

**约束**：骨架层关系禁止使用 `#领域推断`。

### 语义描述（必填）

每条关系必须附一句机制说明，禁止笼统词（"相关""影响""有关联"）：

```
✅ → 机制: MCR² 的率缩减目标函数在 CRATE 中被展开为 MSSA 算子（压缩）与 ISTA 算子（稀疏化）的交替迭代
❌ → 信息论"相关"于控制论
```

### 佐证论文（可选）

关系可附 `papers` 数组字段（论文名/ID 列表），viewer 在机制说明下方渲染为参考文献条：

```
"mechanism": "MCR² 的率缩减目标函数在 CRATE 中被展开为 MSSA 算子（压缩）与 ISTA 算子（稀疏化）的交替迭代",
"papers": ["CRATE: 以冗余率缩减为目标的自监督学习", "White-Box Transformers 结构"]
```

## 四、分层递进构建流程

```
第一层 · 骨架层（3-5 个最高级节点）→ 用户确认骨架 + 关系
第二层 · 展开层（每个骨架的子知识）→ 用户确认子节点划分
第三层 · 实例层（具体案例/论文）→ 确认后归档
```

**骨架层识别标准**：这个概念删掉后，整个知识体系是否崩塌？不会 → 不在骨架层。

## 五、常见陷阱

| 陷阱 | 说明 |
|------|------|
| 方法误判为框架 | 如把"因子定义"放骨架层，但它是管线中的一环 |
| 硬造因果关系 | 两个节点存在 ≠ 有因果，每条关系需标注证据等级 |
| 关系方向反了 | 验证："A 的推进是否需要 B 先行" |
| 一次性生成 | AI 一次读完长文档→抽节点→写关系，无法标注来源、无法逐层确认 |

## 六、可视化规范

- 双栏布局：左侧结构树（300px）+ 右侧力导向图
- 节点颜色 = tags[0] 对应标签色；状态圆点（绿=fulfilled 黄=growing）
- 关系颜色按类型区分；冲突线合并双箭头
- 交互：拖拽/缩放/悬停高亮/点击详情
- 时间线视图：X 轴年代，节点按 `year` 定位，成熟度用边框样式区分
